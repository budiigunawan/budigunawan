# Project is the unit of evidence; a Work Entry is a timeline

Every piece of shipped software is a Project, classified `personal` or `professional` and optionally referencing the Work Entry that produced it. A Work Entry describes an employment relationship — company, role, dates, responsibilities — and never owns Projects.

This replaces a schema where Magpie appeared twice, once as a Paragon responsibility and once as a project card. A reader met the same work in two framings with no link between them, and had no way to tell whether Paragon's OMS and the Magpie card were the same thing.

Rejected keeping both with the duplication, because the two copies drift. Rejected collapsing everything into one CaseStudy type, because recruiters scan an employment timeline and that structure would have to be reconstructed from prose.

Consequence: professional Projects must respect client confidentiality — only detail already public may be published.
